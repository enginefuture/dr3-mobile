# Pinned upstream changes

Base: seedds/nxnative `9579030e5b1f0443c12b7376559560915b6d4c4b` (MIT, includes D2R lineage). Changes are applied by `tools/dr3.py bootstrap` from `patches/nxnative.patch`. No original D2R or Bayonetta working files are edited.

- `nvn_mtl.m`: correct the shader dictionary's Objective-C value type to NSString, matching assignment and use; the mismatched NSArray declaration stopped the current clang build.
- `hle.c`, `hle_svc.c`: fail visibly on called unimplemented imports/kernel calls. Unknown service connections include the guest frame-pointer backtrace and port name.
- `loader.c`, `hle.c`: resolve undefined ELF weak imports to null when neither a guest definition nor an HLE definition exists. SDK 8's optional `nnosGetDefaultUserExceptionStackForApplication` is checked for null by `sdk+0x339c84..0x339ca8`; assigning a callable stub incorrectly takes the callback branch. Actual D3 boot advanced beyond this after the fix.
- `patch_nso.py`: record the four in-place CTR_EL0 adaptations as explicit cuts, including original and new bytes. These set the host cache-line policy (DminLine=4); they are intentional adaptations, not claimed register-value equivalence.
- `hle_account.c`: SDK 8 `OpenPreselectedUser(UserHandle*)` returns Result, unlike `TryOpenPreselectedUser`'s bool. Return the existing local user's complete 24-byte handle. The SDK public implementation requires a platform-populated UID and otherwise aborts; D3 calls it at `main+0x4c51cc`. A synthetic C test checks output canaries and GetUserId roundtrip.
- `hle_misc.c`: adapt SDK 8 `CheckFreeCommunicationPermission(bool)` to the host's existing offline policy, returning false. Its SDK implementation tries to connect to `sm:` for the missing pctl service (`sdk+0x33a620`; observed guest backtrace).

The D3 profile uses exact full NSO Build IDs and SHA-256 in `config/diablo3-2.7.7.json`. The Mac address-space profile was increased after observing nninitStartup's 768 MiB allocation fail against the initial 256 MiB alias candidate. This is a virtual reservation policy, not an iPhone memory validation.

# Independent verifier adaptations

Based on d2r-mobile `21cf97b91823111ead237858ea79929afacf71a5`, kept in `third_party/d2r-verify` with its license.

- Read nxnative's BUILD_ID metadata as text.
- Include CTR_EL0 in the independent LLVM census and account for its registered in-place cuts.
- Independently validate the complete ten-instruction nxnative `mov sp,x18` trampoline, including old-SP restoration, key page, scratch registers and exit. The original verifier assumes all temporary restores are SP-relative.
- Filter only the exact 8-byte host thread-slot writes from Unicorn's patched-side memory-write list. The original broad 64 KiB TSD filter hid an unrelated guest write generated by randomized SDK site `0x2cafe0`, producing a false difference. Retaining that write made both results agree. This narrows the exclusion and preserves the original state comparisons and negative controls.

The harness replaces exclusive operations in both inputs. Passing it does not prove hardware exclusive-monitor or concurrent scheduling behavior.

Additional native boot and graphics adapters:
- `hle_audio.c`: report zero microphone capture devices instead of calling the missing audio input service.
- `hle_thread.c`: DestroySystemEvent removes the host event binding before calling the original SDK destructor, allowing D3's temporary event addresses to be reused safely.
- `hle_nvn.c`: provide TextureGetStride, treat stencil cull criteria as an unsupported optimization hint, and fail unknown NVN entry points visibly. TextureFlushTexels marks non-linear pool-backed textures CPU-written; linear textures retain their direct buffer path. This restored the observed UI texture uploads.
- `nvn_mtl.m`: missing stage mappings/libraries are fatal in ordinary runs; shader capture remains an explicit diagnostic mode.
- `dmsh_chain.lock`: record the actual local shader translation toolchain.

Physical input:
- `native/gamepad_mac.m` is adapted from Blade II Mobile's generic GameController backend, copied into the ignored upstream checkout by bootstrap/build. Its separate SHA is recorded in host-build.json.
- `front_mac.m` starts discovery, shows connection state in the title, clears keyboard/controller state on focus loss and polls physical state on return.
- `hle_hid.c` adds explicit held/edge clearing and bounded JSONL receipts of actual connected Npad state returns. Logging uses a mutex; it is for debugging, not performance measurement.
- Host Makefile adds GameController.framework and the adapter. Apple snapshot tests exercise the real framework objects through the guest HID fill routine; they do not stand in for physical button testing.


Live session diagnostics:
- App/CLI enable existing per-frame TSV timings with function-call rows disabled. The controller publication trace uses the same monotonic clock as the guest HID receipt. HID logging capacity is configurable (1024–65536 rows); this debug build selects 65536.
- Deferred program-key computation logs the program address, serial and shader descriptor pointers before reading control data. A live run captured keys_hash -> prog_key dereferencing control address 0x820000; its cause is not yet established. The original crash logs are archived privately.
- Fixed an independent compiler-detected bounds error: RED_ONCE tag 84 requires 85 entries, whereas the upstream counter array held only 84. This does not establish that the observed program-key crash was caused by that counter.


Uniform-forwarding candidate (off by default):
- nvn_uniform_forward.h records exact non-overlapping guest ranges and immutable version bindings; partial overlaps require a flush. It does not enlarge guest NVN objects.
- nvn_mtl.m stages inline uniform bytes in a shared buffer, forwards complete CBUF reads to those immutable bytes, and coalesces the final copies back to original buffers. Read/write/unknown graphics reflection, bindless/driver-dependent resource uses, partial CBUF coverage, vertex/index/texture/attachment aliases and ordering operations flush before continuing. Switching uses a file polled at submission boundaries.
- hle_nvn.c records forwarded update/binding/flush/reject counts into existing frame TSV metrics. All existing shaders, draws, output resolution and TBDR settings remain unchanged.
- tests/test_uniform_forward.m checks production range/version decisions plus a separate real Metal pixel test with direct independent expectations. Live integration and reversibility checks remain required.

Lantern/stability candidate (kept separate from the user-play baseline):
- Track potentially written render attachments, including clears and depth/stencil writes. Before a reflected sample aliases a written attachment, finish the pass and rebuild arguments. This retains uniform forwarding and only adds dependency-driven boundaries. A second diagnostic control value toggles this guard independently; per-frame feedback split counts and bounded shader-key logs expose its cost. Unknown bindings are conservative. The original blue-lantern effect is not yet attributed to a specific draw.
- Snapshot program descriptors and cached stage keys inline at BindProgram recording, and copy them into host-owned active state at execution. Do not defer reads from guest NVNprogram storage until replay. Restore graphics state by recomposing from saved stage identities rather than trusting an evictable composite-cache slot. The guest program ABI is unchanged. The initially separate CopyCommands lifetime gap is addressed by the integration below.
- tests/test_program_snapshot.c protects original object/command pages with mprotect and verifies independent key ownership, relocation and rejected captures. tests/test_uniform_dependencies.m checks real depth-write-to-sample visibility against 64 independently expected pixels and excludes unrelated writes. Offscreen town execution and independent guard A/B are recorded separately from foreground presentation evidence; see LANTERN_STABILITY.md.

Integrated compatibility work (runtime fcffb365d4d29c767abd2378a11ee1042c0e25682374e4c04fec1bd404131749):
- `nvn_command_copy.h`, `hle_nvn.c`, `nvn_mtl.m`: validate and flatten recorded BEGIN/JUMP/CALL chains before copying into target-owned command memory. Source reuse/finalization cannot alter a successful copy. Indirect CallCommands remains distinct. SDK 8.2 SyncInitialize/Wait and queue/command wait semantics are checked against the original implementation; queue dependencies use GPU event waits instead of a CPU drain. See NVN_COMMAND_LIFETIME.md and the two 64-case native GPU fixtures.
- `nvn_vertex_fetch.h`, `nvn_mtl.m`: retain actual vertex formats, adapt generated MSL entry types to float/int/uint fetch classes, and preserve register bits with `as_type`. Chain/base/source/library/SDK checks bind the prebuilt layouts to their source; unknown layouts are compiled once and cached. Three recorded failed PSOs now link; independent GPU register expectations cover 128 channels. Failed PSOs record exact serialized state and reason. No missing varying or texture type is silently fabricated.
- `hle_hid.c` routes only real haptic capabilities to `native/controller_effects.m`, copied by bootstrap/build and hashed separately from the patch. GameController/CoreHaptics implement approximate amplitude/frequency mapping with asynchronous lifecycle cancellation. No fake six-axis or NFC device is advertised. Pure six-axis conversion helpers are independently tested but not published as a hardware backend.
- The host Makefile links CoreHaptics and the shared native effects source. Upstream NVN tests now use the SDK's FAILED=3 result for an initialized/unfenced sync, and re-exec the deliberate unimplemented-API abort probe before Metal initialization.

Local project tooling (outside the upstream patch):
- Strict CPK fragment overlap validation and stored-payload CRC auditing now cover all 51 archives; all 1569 extracted shader hashes remain unchanged. See ROM_AUDIT.md.
- `platform/ios` and `tools/build_ios*.py` build the same locked native host with separately compiled iPhoneOS libraries, separate touch/physical input and resource readiness checks. Successful builds and failed signing attempts have separate receipts. Compilation is not installation or device validation.
- `tools/smoke_mac.py` verifies the candidate identity and runs bounded, offscreen diagnostics on cloned saves. A normal equip/save/quit/reload roundtrip passed; no original save was modified. See SAVE_ROUNDTRIP.md.
- Mac app and CLI launch defaults now explicitly enable uniform forwarding, matching the user's performance priority. The live app control file can still override this for authorized diagnostics. App receipts additionally bind the launcher binary and source; this packaging change does not alter the tested native runtime.
