# Diablo III 2.7.7 ROM 与宿主兼容性审计

2026-10-17，针对本地拥有的游戏文件和当前候选宿主进行只读扫描。初次目录扫描期间没有操纵游戏、重启进程或改变性能开关，也没有解压 CPK 内容或重算约 22.75 GB 归档的全量哈希。游戏进程结束后，另外进行了下述顺序 payload 解码审计；没有提取或保存资源内容。

这份清单建立了可复查的覆盖边界，**不能据此认定全游戏已经完整、稳定**。灯笼闪烁已有用户同场景关/开复现，属于常量转发的画面正确性问题，应继续局部修复并保持性能收益。

## 可重复执行


每次扫描生成 `work/audit/<UTC时间>/`；本次固定证据目录为 `work/audit/rom-compatibility-20261017/`，不纳入公开源码。目录中有 `summary.json`、完整归档目录、去重资源列表、模块符号、宿主注册表、强制接管政策、NVN 覆盖、SVC 包装器和运行警告。工具只读游戏与宿主，写入审计目录。

候选二进制 SHA-256 为 `3e225b37aed860b4dfb1b6876e9a70c1687f9abf8cf73935ff1ebe62d663b23c`。注册指针使用已验证的 `DYLD_CHAINED_PTR_64_OFFSET` 格式 6，解析时检查段、节、链页、指针目标、名字终止和外部绑定序号。检测到的 571 个强制接管名称在 main/sdk 动态符号中存在，其中包含 SDK 自己的定义，**不是 571 个已执行调用**；启动日志另有其自身的重定位命中计数，两者不能混为一谈。

覆盖证据分为四层：

| 层级 | 本次完成情况 |
| --- | --- |
| 宿主注册 | 313 个 NVN 函数有注册实现；这是实现入口覆盖，尚未逐参数、逐资源格式证明语义完整 |
| ROM 引用 | 主模块含 516 个 NVN 名字字符串，其中 187 个在宿主未注册；名字表和字符串不是静态调用证明 |
| 静态调用/数据流 | 本轮未做完整控制流、间接函数指针和逐场景可达性分析，不给出静态实调用总数 |
| 实际执行 | 当前日志累计计数证明 129 个 API 被调用；日志没覆盖的路径仍未验证 |

多数 CPK 资源由保留的原游戏代码解析，并非每一种扩展名都需要宿主重写。77 种扩展名不能当作 77 个未支持格式；同样，目录可读也不能证明贴图/材质/视频等内容在宿主表现等价。

4/5 个未解析弱符号主要是原 SDK 链接器边界标记；SDK 另有默认用户异常栈的可选钩子。不存在强导入缺失不代表没有延迟加载、字符串查找或 ABI 风险。

## 已观察到的画面和稳定性缺口

本次当前会话日志存在 normalized 顶点属性与整数输入不匹配、顶点/片元接口不匹配、顶点属性 `0x27` 与 float 类型不一致，以及着色器纹理声明类型与实绑纹理类型不同的警告。应逐类补齐适配和回归场景，避免仅用“着色器全部编译”代替渲染验收。详细管线键和原始行只保存在私有 `runtime-warnings.txt`。

显示节拍无回调的警告也在当前日志中出现，但需要与前后台状态对齐；不能直接认定前台性能回归。历史 `keys_hash/prog_key` 崩溃和当前灯笼闪烁仍需单独追踪，导入/归档扫描不能解释或排除它们。

## 游戏退出后的顺序 payload 解码审计

已修复严格资源读取器，重新顺序扫描 **51 / 51 个归档全部通过**，包含全部 14 个中文 DLC。共解码 **1,386,014 个扇区、37,143,077,051 个逻辑字节**。工具只读原归档，在内存验证压缩流、解密、扇区输出长度和相邻偏移，不提取或保存 payload。首次全量修复验证用时约 77.5 秒，此数值不代表游戏加载速度。

旧审计 `work/audit/payload-20261017/` 的 41 / 51 是当时严格解析器的停止边界，应作为历史证据保留。原先失败的 Act2、Act4、Act5、Patch2_6_5、Patch2_6_7、Patch2_6_7a、Patch2_7_1、Patch2_7_4、Patch2_7_5、Patch2_7_6 已在新扫描中完成；没有改写 ROM、补零、忽略损坏流或仅跳过问题块。

### 满扇区片段的真实边界

本作锁定 main Build ID `2607a74f…` 的原始反汇编提供了格式证据：

- `0x762e20` 读取 6 字节 CPK 片段头，按声明长度跳到下一片段；其解密种子与本地提取器的数值完全一致。
- `0x763010` 是 CPK 流读取路径；`0x76307c` 把请求长度写入 `z_stream.avail_out`（偏移 `0x20`），`0x763084` 调用原始 inflate（`0x109d0`，flush=0）。`0x7630f8–0x763104` 在满足请求后结束；这里没有要求 `Z_STREAM_END`。
- `0x4afbf4–0x4afc18` 的调用方以不超过 `0x10000` 的逻辑块请求读取，进一步确认物理压缩片段与调用方请求边界不同。

全量扫描发现 **15 个** `packed_length=0x3ffa` 的满扇区 zlib 未终止片段，完整 inflate 会产生额外前瞻输出，合计 **1,567 字节**，最大单片段 **817 字节**。这些额外字节**全部逐字等于后续独立压缩流的逻辑前缀**。这是可验证的重叠，不是可随意丢弃的多余数据。

修复只允许同时满足以下条件的情况：物理扇区已填满、片段没有结束标记、输出大于非零声明值、输入被完整消费且无尾随流，并且每个额外输出字节与后续逻辑流一致。对外返回声明的逻辑区间，额外输出先严格比对才接受。普通短块、已结束流、边界不符、输入未消费、重叠字节不符和重叠越过归档末端全部继续拒绝。

还验证了 **346 个**零长度加密终止标记（`expected=0, packed=0x8000`）。该判断现已统一放入生产严格读取器：只有声明和压缩长度均为零，且扇区余下部分全零才接受；不再通过审计专用代理改写内存片段。

| 证据 | 内容 |

| `shader-byte-equivalence.json` | 使用修复后的读取器重读原回执中的 1,569 个 SHD，全部内容 SHA 与既有回执相同；没有覆盖 shader 源或缓存 |

新增解码器身份保护后，再次完整扫描的最终回执为 `work/audit/payload-verified-crc-20261017/summary.json`。恢复任务现在同时核对输入大小/修改时间和解码器源码 SHA，不能复用旧实现的“已完成”结果；旧回执无此身份字段时必须使用新目录重扫。

CPK 测试共 9 项，payload 审计测试共 11 项。新增正反对照覆盖满扇区有效重叠、重叠字节不符、越过归档末端、完整 zlib 流不能借用重叠例外、普通超长块仍失败、缓存命中时诊断准确，以及旧解码器/变化输入的恢复拒绝。既有损坏流、空标记非零尾随、映射边界等拒绝测试保留。

### 归档存储 payload CRC

已独立确定头部 `+0x38` 的 CRC 覆盖：从首个物理压缩扇区到文件 EOF 的**全部原始存储字节**，包含加密字节和扇区填充，不包含头部/索引前缀；算法为 IEEE CRC-32（`zlib.crc32`，初值 0）。51 个归档全部与各自存储 CRC 一致。独立只读核对证据在 `work/audit/payload-overlap-20261017/compressed-payload-crc.json`，正式扫描工具也已在解密/inflate 前执行该校验。测试故意修改压缩数据及扇区填充均拒绝，修改覆盖范围以外的索引前缀不影响此项 CRC；索引仍须通过自己的结构边界验证。

**验收范围**：完整解码证明当前归档的压缩流与逻辑输出边界在本读取器下成立。该修复针对离线严格资源提取/审计工具；运行游戏本身继续使用原 CPK 读取代码，不能写成修复了“运行时 ROM 损坏”。输出 SHA 是回执，没有与独立可信资源清单对照。完整 zlib 流验证自身 Adler 校验，未终止片段靠输入、长度、映射和重叠约束验证；归档压缩 payload CRC 已全部通过，但其覆盖不包含头部/索引，不能扩展成整文件可信校验。全部解码通过仍不证明每个贴图、材质、视频、音频的运行语义或全游戏稳定。

## SDK SVC 边界

main 原始 text 未发现 SVC 指令；sdk 有 61 个 SVC 指令点。与当前 `hle_svc.c` / `hle_thread.c` 明确分派分支作静态对照，其中 25 个编号没有分派分支。

这是 **SDK 包装器潜在回退边界**，不能写成“游戏必经 25 个未支持系统调用”。服务接口被强制接管后，许多包装器不会执行。需要保存未支持调用的实际日志、调用栈或可靠的静态调用路径，再决定应补实现还是有意离线返回。原始站点与编号见私有 `svc-wrapper-coverage.json`。

## 后续验收顺序

1. 保持常量转发性能路径，修正灯笼相关的局部资源依赖或常量版本问题；同场景进行画面与帧时间反向验证。
2. 修复已经出现的管线、顶点格式与纹理维度不匹配。对对应材质和光照建立可重复场景。
3. 在用户可选的离线功能范围内，覆盖五幕、过场视频、传送/换图、首领、背包/装备、存读档、死亡复活、长时间游玩及前后台/手柄重连。主线和冒险模式、职业/技能组合、多控制器要分别记录覆盖。
4. 完整性边界明确列出联机、好友、本地无线、amiibo、震动、六轴等未支持功能；每项实现后才改变状态。
5. 51 个归档已全部完成严格解码及边界验证；归档存储 payload CRC 也已全部通过；继续资源运行语义验收。解码成功仍没有证明其它资源容器内部不含着色器或驱动特例。

解析器测试包含两个正对照及 33 个故意破坏的边界变体，覆盖错误 Mach-O 头、载入命令大小、链格式/段地址/跨页、缺失 fixup、错误绑定序号、越界/无终止字符串、非法路径、CPK 数量/扇区/成员范围。测试通过只证明审计工具的这些拒绝边界，不证明游戏稳定。

后续源代码修复：上述 NVN 同步空实现属于本次审计时候选二进制的事实。之后的同步/Copy 生命周期修复、原 SDK 返回值证据及独立 GPU 测试见 [NVN_COMMAND_LIFETIME.md](NVN_COMMAND_LIFETIME.md)。该修复不把初次审计的 313 项入口计数追溯改写成全语义覆盖。
