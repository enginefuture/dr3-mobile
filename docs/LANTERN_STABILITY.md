2026-10-17。当前策略是保留常量转发的性能收益，在独立候选中补资源依赖和程序生命周期。没有修改原始游戏文件或正式存档。原游玩 PID 20097 已退出，最后记录已归档，监视自动化已暂停；以下运行均为无窗口、隔离存档的诊断进程。

后续整合候选为 `work/macapp-complete/DR3 Mobile.app`，runtime `fcffb365d4d29c767abd2378a11ee1042c0e25682374e4c04fec1bd404131749`。除本文修复外还包括真实命令复制/同步和顶点 fetch 适配。转发及附件守卫始终开启的 110 秒城镇测试无崩溃/红告警，末 30 秒为 442 draw / 56 pass / 1 个依赖边界，GPU p50 3.959 ms。隔离装备存读档闭环也已通过，详见 [SAVE_ROUNDTRIP.md](SAVE_ROUNDTRIP.md)。这些测试保留了 pass 收益，仍不替代原蓝灯的同位置动态验收。

## 已确认的现象

用户在同一位置观察到：常量转发开启时灯笼本体、边缘或阴影闪烁；关闭后消失；重新开启后恢复。这证明闪烁与该优化有关，尚未定位到蓝灯对应的绘制或资源。静态截图不能证明时间上的闪烁消失。

旧路径对 uniform 的 GPU copy 会结束 render pass。转发路径消除了这些 copy 边界，但原有附件反馈检测仅在合并 pass 路径执行，本作关闭该路径且 `feedback_snap` 为空。因此，一个原本依靠 copy 边界获得可见性的“附件写入→采样”依赖可能暴露。它是代码支持的具体假设，不能直接当作蓝灯根因。

## 保留性能的候选处理

转发继续开启。候选记录当前 pass 真正可能写过的颜色、深度/模板附件，依据实际阶段反射检查后续纹理/图像读取，按纹理 serial 或底层 guest 地址重叠识别别名。仅在读取已写附件时，写回必要常量、结束 pass 并重建参数。清除操作也计入写入，单纯只读深度不持续触发拆分。未知绑定采取保守处理。计数为 TSV 的 `@uf_feedback_splits`。

隔离诊断控制文件支持 `1 1`（转发开、依赖守卫开）、`1 0`（转发开、守卫关）。这次性能对照始终保留第一个 `1`，没有全局关闭转发。不能把该控制文件混同于原游玩控制文件。

新增独立 Metal 测试先写入深度 0.25，再结束 pass 并由只读深度绘制采样；64 个像素均与独立预期 RGBA 64/128/191/255 相符。另测无关颜色写入不触发深度依赖、地址重叠/溢出及未知范围。此测试覆盖基本 GPU 依赖语义，未覆盖完整游戏全部材质。

## 独立发现并修复的程序寿命问题

首轮离线候选 `9da1501e…` 在进入游戏时复现 SIGSEGV：`keys_hash → prog_key → prog_get → state_op`。诊断中 NVNprogram magic 已被覆盖为 `0xa9`，描述符为明显失效值，记录的 BindProgram 仍持有原 guest 指针。原始证据在 `work/run/lantern-offscreen-20261017-205403/boot.log`。这是比先前只有异常 control 地址更直接的失效存储证据。

新记录在 BindProgram 时捕获程序描述和阶段键，内联在宿主命令中；回放再复制到宿主拥有的活动阶段状态，避免命令内存复用影响当前绑定。完整状态恢复也从保存的阶段重建有效合成程序，避免预编译探测淘汰 `cp[64]` 后恢复了另一组 shader 的槽位。guest NVNprogram ABI 未扩大。

C 测试实际用 `mprotect(PROT_NONE)` 禁止读取原对象和原命令页，再验证搬迁记录、活动阶段键、失败捕获不发布半状态及空解绑。未缓存键的首次捕获仍要求 BindProgram 入参当时有效。真实 `CopyCommands` 目前与 CallCommands 同样保留原 handle，尚未实现完整源命令复制；本测试不证明该 API 的源命令内存寿命已修复。

修复版的 60 秒无窗口测试已进入城镇并越过上述崩溃点。该轮结束的 `CRASH sig=14` / exit 142 是显式设置 `DM_WATCH=60` 后由诊断闹钟产生，不能算作新的游戏自发崩溃。后续对照改由外部测试脚本在时限后终止自己的进程。短时通过不能证明长期生命周期问题全部消失。

## 实际场景证据与剩余验收

修复版城镇在帧 1208 起触发深度附件依赖，日志为 `mask=0x100`、VS `1013de8c384544aa_b` / PS `d8f29766e7945ec9_b`，随后稳定场景约每帧一次。帧 1800 的离屏输出已确认进入城镇，约 442 次绘制，GPU 中位约 4.5 ms。它证明守卫命中了实际绘制，不证明这组 shader 对应用户截图中的蓝灯。

该阶段的代表性原始容器是 `Patch2_6_8.cpk:Shaders\\particle_additive_soft_biased.shd`（SHA `3c74a454…`）。生成 PS 实际 gather 第一张纹理，在屏幕坐标位置读取数值，与粒子深度组合计算 alpha，随后按阈值 `discard_fragment()`；依赖检测确认所绑纹理与刚写的深度附件别名。这说明软粒子的淡出边缘确实依赖场景深度，缺少可见性边界有能力改变它的透明度/边缘。文件名只是去重阶段的代表来源，仍不能由此给蓝灯作确定归因。

同进程守卫开关对照的私有脚本：`work/run/lantern-offscreen-ab.py`。完整指标和运行 SHA 以 `work/run/lantern-guard-ab-*/summary.json` 为准。无窗口模式没有实际上屏 FPS，不能把固定 60 Hz 的整帧节奏当作前台 60 FPS 验收。
